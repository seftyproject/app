Demo con Expo Go

Preparare e avviare la demo Sefty con Expo Go.

Istruzioni riassuntive

Sefty — Guida alla demo con Expo Go

La demo funziona con un computer Windows o Mac e telefoni iPhone/Android, anche su Wi-Fi diversi o rete mobile. Il computer deve restare acceso e connesso a Internet.

1. Preparare computer e telefoni

Aggiornamento Android del 22 settembre 2026: corretto il blocco di avvio relativo alle notifiche push in Expo Go. Per aggiornare una cartella già utilizzata, fermare la demo con Ctrl+C e copiare i file della nuova consegna nella cartella esistente, conservando sefty-backend/.env e il database Docker. Riavviare con npm run demo e scansionare il QR corrente.

Se si estrae la ZIP in una cartella nuova sullo stesso computer, l'avvio recupera automaticamente la configurazione dalla precedente installazione Docker, anche dopo un normale spegnimento dei servizi. Conservare la cartella precedente fino alla verifica della nuova. Se i container precedenti sono stati eliminati o erano già in errore, può essere necessario copiarne il file sefty-backend/.env: il programma lo segnala senza generare password incompatibili. Non cancellare il volume del database.

Mappa Android: su un telefono l'app si apre ma non carica strade e nomi, pur mostrando segnalazioni e zone. Questo problema non è risolto dalla correzione delle notifiche. Prima della presentazione verificare la cartografia sui telefoni scelti; i dettagli del controllo sono in REVISIONE_I3P.md.

Sul computer installare:

  • Node.js: versione 24 LTS, oppure 22.13 o successiva della serie 22.
  • Docker Desktop: versione adatta a Windows o Mac. Su Windows usare i container Linux e completare l'eventuale configurazione WSL2 richiesta da Docker.

Sui telefoni installare Expo Go compatibile. Prima della presentazione provare gli stessi dispositivi che verranno utilizzati.

Estrarre la cartella DemoSefty in una posizione locale, ad esempio Documenti. Non avviare il progetto dentro un file ZIP.

La ZIP contiene il progetto e le guide, senza password, account personali o database di prova. Su un nuovo computer il primo avvio genera la configurazione e un database vuoto: registrare gli utenti Sefty da usare nella presentazione. Gli avvii successivi conservano i dati inseriti.

Aprire Docker Desktop e attendere che il motore sia avviato.

2. Creare l'account Expo dedicato a Sefty

Questa operazione va eseguita una sola volta per la demo.

  1. Aprire expo.dev/signup.
  2. Usare un indirizzo email gestito dal team Sefty e scegliere un nome riconoscibile, ad esempio sefty-demo se disponibile.
  3. Impostare una password dedicata, completare la registrazione e l'eventuale verifica email.
  4. Conservare le credenziali nel gestore password del team e renderle disponibili alle persone che preparano i telefoni. Non inserirle nei file del progetto.

L'account Expo serve ad aprire il progetto in Expo Go. Non servono un account Apple Developer o un piano di build a pagamento.

Usare lo stesso account Expo sul computer e in Expo Go su tutti i telefoni della demo. Questo requisito è obbligatorio su iPhone con Expo Go SDK 57 (annuncio Expo).

Gli account Sefty sono separati da Expo: utilizzare due utenti Sefty diversi per provare contatti, SOS, Hug e gruppi.

3. Collegare il computer all'account Expo

Aprire un terminale nella cartella DemoSefty, quella che contiene questo documento e package.json.

  • Windows: aprire la cartella in Esplora file e scegliere «Apri nel terminale» dal menu contestuale. In alternativa aprire PowerShell e usare cd "percorso della cartella DemoSefty".
  • Mac: aprire Terminale, digitare cd seguito da uno spazio, trascinare la cartella DemoSefty nella finestra e premere Invio.

Eseguire:

npm run demo:login

Il comando installa le dipendenze mancanti. Il primo avvio può richiedere alcuni minuti. Completare il login Expo seguendo le istruzioni del terminale, usando l'account dedicato alla demo. Se si apre il browser, verificare di selezionare quell'account.

Per controllare l'account:

npm run demo:account

Il nome mostrato deve essere quello dell'account dedicato Sefty. Se compare un altro account, ripetere npm run demo:login con quello corretto.

Su Windows: se PowerShell blocca npm.ps1, sostituire npm con npm.cmd in tutti i comandi, ad esempio npm.cmd run demo:login. Non occorre modificare le impostazioni di sicurezza di PowerShell.

4. Collegare i telefoni allo stesso account

Su ogni telefono:

  1. Aprire Expo Go e toccare l'avatar in alto a destra.
  2. Se è presente un account personale diverso, effettuare il logout.
  3. Accedere con l'account Expo dedicato a Sefty.
  4. Verificare che il nome utente coincida con quello mostrato da npm run demo:account sul computer.

Le vecchie voci Sefty nella cronologia non impediscono il funzionamento. Utilizzare il QR generato dal nuovo avvio.

5. Avviare la demo

Con Docker Desktop aperto, dalla cartella DemoSefty eseguire:

npm run demo

Il comando controlla l'accesso Expo, avvia il database e gli altri servizi, apre il collegamento Internet del backend e genera il QR di Expo Go. Al primo avvio vengono scaricati anche i componenti Docker: attendere il completamento.

Non occorre installare ngrok manualmente, creare un account Cloudflare o modificare indirizzi nei file.

  • iPhone: scansionare il QR con Fotocamera e aprire il collegamento in Expo Go.
  • Android: aprire Expo Go e utilizzare la funzione di scansione del QR.
  • Attendere il caricamento dell'app; la prima volta può servire più tempo.
  • Dentro Sefty, registrare o utilizzare un account diverso su ciascun telefono.
  • Consentire la posizione precisa durante l'uso dell'app e le eventuali notifiche locali richieste.

Mantenere le app aperte in primo piano, il terminale aperto e il computer collegato all'alimentazione. Disattivare la sospensione e non chiudere il coperchio del portatile. Non avviare più copie della demo contemporaneamente sullo stesso computer.

Il QR può cambiare dopo un riavvio: usare sempre quello corrente. L'indirizzo «Backend HTTPS» stampato nel terminale è configurato automaticamente e non va scansionato al posto del QR.

6. Preparare la presentazione

La barra inferiore contiene cinque comandi:

  • mappa: torna alla posizione attuale e chiude le informazioni della zona.
  • giorno, con il simbolo del sole: apre gruppi e sessioni condivise.
  • SOS: invia la richiesta di allarme.
  • contatti, con il simbolo del gruppo: apre contatti fidati e richieste in attesa.
  • rientro, con il simbolo del timer: apre il timer di rientro.

Toccare una circoscrizione sulla mappa per mostrarne le informazioni. Il menu in alto a sinistra contiene le impostazioni e si chiude toccando la mappa, scorrendo verso sinistra o premendo la X.

Eseguire una prova completa prima della presentazione, con un telefono sulla rete mobile e l'altro sul Wi-Fi:

  1. Aprire Sefty su entrambi e accedere con due utenti distinti.
  2. Aggiungere il secondo utente ai contatti fidati e accettare la richiesta dall'altro telefono.
  3. Inviare un Haptic Hug e controllarne la ricezione.
  4. Inviare un SOS, premere «Intervengo» sull'altro telefono e verificare la conferma. Chiudere il SOS e controllare che scompaia da entrambi. Non attivare la chiamata al 112 durante la prova.
  5. Inviare una segnalazione sulla mappa e verificarla sull'altro telefono.
  6. Creare un gruppo Sefty Giorno, far entrare il secondo utente tramite invito, avviare e terminare la sessione. Provare il GPS all'aperto; al chiuso non basare la presentazione su distanze di pochi metri.
  7. Impostare il timer a un minuto e attendere anche i 30 secondi di verifica. Sui due telefoni compare «Rientro non confermato» nella mappa di Sefty. Sul telefono del contatto premere «Intervengo»: il nome compare nella scheda su entrambi. Sul telefono che ha avviato il timer premere «Sto bene · avvisa i contatti» e verificare la chiusura su entrambi. Ripetere confermando «Sono arrivato» prima che scadano i 30 secondi: non deve partire alcuna allerta.
  8. Cambiare rete a un telefono, tornare nell'app e inviare un altro Hug per verificare la riconnessione.

Preparare gli account Sefty sullo stesso computer che ospiterà la presentazione: i dati restano nel suo database.

Allerta di rientro

L’allerta rimane dentro Sefty e riguarda soltanto la persona che ha avviato il timer e i suoi contatti fidati al momento dell’invio. Non viene inviata agli utenti nelle vicinanze. La scheda indica l’ultima posizione disponibile e quanto tempo è passato dalla rilevazione; se il GPS manca, lo segnala senza mostrare una posizione fittizia.

«Intervengo» registra la presa in carico e mostra il nome del contatto. La persona interessata può chiudere l’allerta con «Sto bene · avvisa i contatti»; un contatto intervenuto può usare «Conferma che sta bene» dopo averlo verificato. «Mostra mappa» nasconde la scheda, senza chiudere l’allerta: per riaprirla, toccare la voce sotto la barra superiore.

Le allerte già registrate e ancora aperte si recuperano alla riconnessione, anche se il contatto era offline all’invio. Un tentativo ripetuto dopo un errore di rete usa la stessa allerta. Se non ci sono contatti fidati, viene indicato chiaramente: nessuno è stato avvisato.

Funzioni e limiti

  • SOS, Hug e aggiornamenti in tempo reale richiedono le app aperte e connesse. Gli eventi inviati a un telefono offline non hanno consegna garantita.
  • Il timer funziona sul telefono: se l'app viene sospesa, l'invio può essere ritardato fino alla riapertura.
  • Le notifiche push remote ad app chiusa e il GPS in background non fanno parte di questa demo.
  • Il bracciale e i Tag Bluetooth reali non sono collaudati; l'associazione di un codice nell'app non equivale a una scansione Bluetooth.
  • Il recupero password non invia email reali. Preparare e conservare le credenziali degli utenti Sefty prima della presentazione.
  • I tunnel richiedono Internet e possono subire interruzioni. In caso di errore, riavviare e ripetere la prova.

La dashboard sul computer è disponibile su localhost:8000/app/; è separata dall'app mobile. Per una presentazione di riserva aprire exports/sefty_demo.html: le slide non richiedono il backend, ma non sostituiscono la demo interattiva.

7. Spegnere e conservare i dati

Nel terminale della demo premere Ctrl+C. Poi eseguire:

npm run demo:stop

Account, contatti, gruppi e altri dati rimangono nel volume Docker del computer. Non vengono ricreati a ogni avvio. Non usare docker compose down -v e non eliminare il volume del database da Docker Desktop.

Su un nuovo computer il database parte vuoto: copiare la cartella non trasferisce gli account Sefty. Per mantenere gli stessi dati occorre un backup e ripristino del database. L'accesso allo stesso account Expo non sincronizza i dati Sefty.

9. Un altro computer o un aggiornamento

Usare una copia dei sorgenti senza node_modules, .expo, .npm-cache, dist-review e log. Non sovrascrivere sefty-backend/.env di un'installazione esistente: contiene la configurazione del suo database.

Su un computer nuovo ripetere la preparazione e npm run demo:login. Il file .env del backend viene creato automaticamente se manca.

Per questo aggiornamento le dipendenze restano identiche alla prima consegna. Dopo aver copiato i file nella cartella esistente basta:

npm run demo

In una cartella appena estratta, lo stesso comando installa automaticamente le dipendenze mancanti.

Su Linux servono Docker Engine con Compose v2 e Node.js; i comandi sono gli stessi. PostGIS richiede amd64: su Linux ARM serve l'emulazione, gestita invece da Docker Desktop sui Mac Apple Silicon. I test automatici sono stati eseguiti su Windows; resta necessaria la prova sul computer e sui telefoni scelti.
